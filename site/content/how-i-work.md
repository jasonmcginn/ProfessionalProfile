  <h1>One approach, applied to very different problems.</h1>
  <p class="hook">Twenty-plus years across networking, systems, cloud and automation. The problems change; the core way I work them doesn't.</p>
  <section id="why">
    <p class="sec-label">// principles</p>
    <p class="sec-sub" style="max-width:none;">These six principles are that approach, in the order I apply them, each one shown in real work.</p>
    <ol class="principles">
      <li><span class="pr-h">Know it to the core.</span><span class="pr-d">I take neglected systems apart until I know them cold, then rebuild them so a fault traces cleanly from the wall jack to the switch port. Untangling the mess is how I come to trust it.</span><a class="pr-link" href="/stories/rack-rebuilds/">see it in the rack rebuilds &#8594;</a></li>
      <li><span class="pr-h">Secure it by default.</span><span class="pr-d">I find exactly what a system needs to run, then grant only that and lock the rest down. Least privilege, enforced by policy rather than trust.</span><a class="pr-link" href="/stories/sage/">see it in the Sage lab &#8594;</a></li>
      <li><span class="pr-h">Deliver it methodically.</span><span class="pr-d">Diagnose, document, propose, verify, in that order. I work a problem end to end and write it up, so the fix is something anyone can check and repeat.</span><a class="pr-link" href="/documents/kindergarten/">see it in the kindergarten proposal &#8594;</a></li>
      <li><span class="pr-h">Build it around people.</span><span class="pr-d">I don't just run technology; I shape it so it works for people without them having to think about it. Nothing beats watching someone get time back every time a solution I rolled out kicks in.</span><a class="pr-link" href="/stories/qos/">see it in the QoS fix &#8594;</a></li>
      <li><span class="pr-h">Build the tools that build the next ones.</span><span class="pr-d">Tools exist to move you toward a goal, and getting there usually takes tools working with other tools. I like building the one that makes the next one easier.</span><a class="pr-link" href="/stories/provisioning/">see it in the account provisioning &#8594;</a></li>
      <li><span class="pr-h">Document it and teach it.</span><span class="pr-d">Documentation, training and tested backups come with every deployment. A solution isn't finished until someone else can run it.</span><a class="pr-link" href="/stories/config-docs/">see it in the handover documentation &#8594;</a></li>
    </ol>
  </section>
