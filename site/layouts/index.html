// 02 discovery to handover

Every project starts with a conversation.

Five steps carry that conversation through to a finished, documented solution. Open any step to see what it means and where I've done it.

01The conversation- the people who do the work, and what gets in their way▸

I start with the people who do the work: where technology is getting in their way, the tools they use today, and who uses them.

where I've done it

  • Thinkmax: discovery through each client's technical leads, hands-on access and their own documentation, for about a dozen Dynamics 365 projects.
  • A business couldn't reach its own resources and nothing obvious was wrong, so I watched the traffic until the cause showed itself. The QoS fix →
  • A teacher was logging a class of twenty-one five-year-olds in by hand, every session. I worked it end to end before proposing anything. The proposal →
02Discovery and design- each pain point followed to its source▸

I follow each pain point to its source, until there is a clear path to success. Possible solutions are compared, including keeping what already works.

where I've done it

  • Thinkmax: a migration and development infrastructure plan for each project, delivered to the project lead.
  • An app that demanded local admin, and students who couldn't have it. I monitored exactly what it needed and granted only that by Group Policy. The Sage lab →
  • Rather than just flag it, I proved our WEP wireless was crackable to make the case for replacing it. The WEP assessment →
  • A site-to-site VPN on a Cisco router, built and tested offline before it went live. The VPN build →
03A clear scope and estimate- written down before any build begins▸

Before any build begins, it is written down: what will be delivered, what is not included, the schedule, and the hours for each part. Any change asked for later is estimated and agreed before it is done.

where I've done it

  • Thinkmax: hours estimated for each component, and released by the project lead as each phase started.
  • New or unseen needs got their own estimate and approval, and the work stayed close to the approved hours.
  • The Controller needed deeper reporting, and outside help ran about $300 an hour. I made the case to build it in-house with PHP and SQL. The reporting build →
04Build and deploy- built and tested before it reaches people▸

The solution is built and tested before it reaches people. Backups are proven before anything old is retired, and each person and system gets only the access it needs.

where I've done it

  • A new ESXi host, RAID 10, fresh VMs, a domain-controller cutover by promote and demote, and backups test-restored before anything old was retired. The server refresh →
  • Development, Test, QA, Pre-Production and Production environments on Azure, with Conditional Access limiting each group to what it needed. The Azure foundations →
  • An on-premises Exchange to Exchange Online migration for a managed services client.
  • The network side of a municipal VoIP rollout: a dedicated voice VLAN, WatchGuard rules, and a fault found in the logs. The VoIP rollout →
05Handover- documentation and training, always included▸

Documentation and training are always included. The people who use it, and the technicians who support it, get something they can follow.

where I've done it

  • Handover documentation produced from a database I filled in as each configuration was confirmed: SQL built the dataset, XML carried it, and Word turned it into the guide. The handover documentation →
  • A three-lab progression I built on my own evenings, so students learned networking by building it. The teaching labs →
  • This site's own process is written down and public: the local loop, the build check, versioned releases and rollback. The development process →
